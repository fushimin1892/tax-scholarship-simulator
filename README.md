# 住民税・所得税・国民健康保険・JASSO奨学金 判定シミュレーター

収入と控除を入力すると、**所得税**・**住民税（均等割／所得割）**の課税額、
**国民健康保険料の軽減割合**、**JASSO給付奨学金・授業料等減免の支援区分（第Ⅰ／Ⅱ／Ⅲ／Ⅳ区分）**
を判定し、結果を **PDF に保存** できるローカルサイトです。

## 開発者向けの入り口

- 画面と入力処理: `index.html`、`css/`、`js/app.js`
- 計算と参照データ: `js/calc.js`、`data/`
- 文書の現行・過去の区別: [docs の読み方](docs/README.md)
- 検証の実行方法: この README の「テストの実行」

公開先: https://fushimin1892.github.io/tax-scholarship-simulator/

### 公開サイトの実測（Lighthouse）

公開していたサイトを計測した結果。

| | パソコン | スマホ |
|---|---|---|
| Performance | **100**（3回とも） | 96（8回測って 93〜98） |
| Accessibility | 100 | 100 |
| Best Practices | 100 | 100 |
| SEO | 100 | 100 |
| CLS（読み込み中のずれ） | 0 | 0 |
| TBT（固まる時間） | 0ms | 110〜270ms |
| FCP（最初の表示） | 0.5秒 | 1.5秒 |

robots.txt は、クローラーも Lighthouse も**ドメイン直下**（`https://fushimin1892.github.io/robots.txt`）しか読まないため、
このリポジトリには置いていない（置いても読まれない）。ドメイン直下にも robots.txt がないので、検索エンジンは「すべて許可」として扱う。
Lighthouse は robots.txt を**ページの中から fetch** して確かめるので、
CSP に `connect-src 'self'`（通信先は自分自身のみ）を足してある。
`default-src 'none'` はそのままなので、入力内容が外に出ないことは変わらない。

スマホが 96 で頭打ちなのは、**最初の1画面を出すまでに、日本語の大きなフォームを
一度組み立てる必要がある**ため。4倍遅いCPUを想定した計測なので、ここが 1.5秒かかる。
これを削るには初期表示に出す量を減らすしかなく、「収入も控除も最初から全部見えている」
という作りと引き換えになる。実測して確かめた結論：

- 要素を847個消した診断版でも 90点にしかならず、**DOMの量は主因ではない**
- 主因だったのは起動時の一括処理で、区切って進めるようにしたら 84 → 96 に上がった

残っている減点は次の3つ。いずれも設計方針とのトレードオフ。

| 項目 | 状況 |
|---|---|
| DOM 2,179要素 | 収入・控除・家族構成を画面に出したままにする方針のため（計測は2026年11月の画面改善の前。改善後は自動で出る結果・1ページずつの入力の部品・あてはまるものの選択の分だけ増えている。`browser-check.js` の上限は 3,500。機能を足して超えたら、理由を書いてそのつど上げる） |
| CSS/JSが未圧縮 | ビルド工程を持たない方針（配ったファイルがそのまま読める）。圧縮すると 19KB 減る |
| キャッシュの有効期間 | GitHub Pages は HTTP ヘッダーを設定できない（10分固定） |

効果がないと分かったので**入れていない**もの（すべて実測）。

- `content-visibility` で画面外を後回し → 画面外に88%の要素があるので効きそうだが、実測すると
  TBT が 280→506ms に増えて総合点は下がる（節ごとに実測した高さを与えても同じ）。
  ステップナビの現在地表示が全節の位置を読むため、結局は組み立てが起きるうえ、
  後回しの管理コストだけが乗る
- スクリプトに `defer` を付ける → ローカルでは FCP 2.7→1.4秒で有効に見えるが、これは
  **テスト用サーバが HTTP/1.1 で読み込みが直列になる**ため。HTTP/2 の GitHub Pages では
  もともと FCP 1.5秒で、defer にすると処理が最初の表示より後ろに移り TBT だけ悪化する
- `word-break: auto-phrase` / `palt` / `tabular-nums` / `text-spacing-trim` を切る → 条件を交互に測ると差なし。最初に見えた差は Chrome のウォームアップで、無害なCSSを入れても同じだけ速くなった

## 税制データの保守

公表資料との突合は、毎月1日を目安に実行します。

毎月1〜6日に、クラウドの定期実行（Claude のルーチン「【毎月】税制データ 全地域確認と更新」）が
下の手順で公表資料と突き合わせ、確認日の更新と公開まで行います。手で行うときも同じ手順です。

確認の手順：

1. `node test/check-updates.js` … 国税庁・JASSO・国保の公表ページと収録値を突合
2. `node test/verify-prefectures.js` … 47都道府県の超過課税を突合
3. `node test/check-cities.js` … 総務省「市町村民税及び固定資産税の税率等別市町村数調」の最新版に載る
   超過課税・減税の市区町村が、`data/tax-data.js` の `CITIES` に同じ税率で登録されているかを突合
4. PDF でしか出ない資料（下記）は公表時期に手で開いて確認
5. **未登録の市区町村が見つかったら、必ず追加する**（「要追加」の行）。
   総務省の調査は前年4月1日現在なので、その自治体の公式ページで今年度の税率・適用期間を確かめてから
   `CITIES` に書き（`check-cities.js` が書く形の候補を表示する）、`test/verify-calc.js` に境界のテストを足す。
   制度が終わった団体（「要確認」で総務省の一覧にない）は公式資料で確かめて特例を外す
   計算や数値を直したときは、[docs の読み方](docs/README.md) の決まりに従ってテストと docs も直す（`node test/audit.js` が直し忘れを止める）
6. 修正を反映し、すべて確認できたら**確認日を更新する**（下のスクリプト）。
   続けて README の確認記録（確認日・件数・直したこと）を書き換え（前回の記録は docs/01 の「過去の月次確認の記録」の先頭へ移す）、main へ push して公開サイトに配信する。
   ヘッダーの「最終更新」は配信日で自動、「税制データの最終確認」は下のスクリプトで更新される

**税率・控除額そのものは自動更新しません**（誤った値が自動で入り、テストもその値で
通ってしまうと誰も気づけないため）。自動で進めるのは「いつ突き合わせたか」の日付だけで、
それも「変更なし◯件 / 要確認 0 / 取得失敗 0」という集計行が出たときに限ります
（スクリプトが途中で落ちた回を「ズレなし」と取り違えないため）。

ヘッダーの「最終更新」は、サイトを最後に配信した日です。更新を反映するたびに自動で変わります。

サイトのヘッダーには「税制データの最終確認日」と「次回の確認予定日（最終確認日の次の1日）」が
出ます。予定日を過ぎると、自動で注意表示に切り替わります。

| 次に確認すべきもの | 公表時期 |
|---|---|
| 茨城県・岐阜県・和歌山県の超過課税の延長（令和9年度以降） | 2026年11〜12月の県議会 |
| 令和9年度税制改正の大綱（財務省） | 例年12月末 |
| 令和9年度の国民健康保険の軽減判定基準額・賦課限度額（政令改正） | 例年3月末 |
| 自治体の令和9年度課税の公式計算例（横浜市・名古屋市） | 例年5〜6月 |
| 2028年度進学の JASSO 支援区分 | 例年春〜夏 |

手で確認したときは、日付も手で進めます（`sed` ではなくこのスクリプトを使ってください。
未来日・巻き戻し・書き損じを弾きます。Windows の CRLF 改行でも動くように直しました）。

## 使い方

`index.html` をダブルクリック（またはブラウザにドラッグ＆ドロップ）するだけで動きます。
サーバー不要・インターネット接続不要・外部送信なしです。

**1ページずつ質問に答えて進む**形です（2026年11月から）。**入力すると結果が自動で計算し直されます**（ボタンを押す必要はありません）。
開くと最初は**表紙**（サイトの説明）だけが出ます。**［入力をはじめる］**で「1 立場」へ進みます。
画面の下の［← 戻る］［次へ →］で進みます。上のナビからは、**一度通ったページにだけ**戻れます（まだ入力していないページや結果へは飛べません）。結果のページへは、最後の入力ページの［次へ：判定結果を見る →］から進みます。
**4 所得・5 所得控除と、6〜8 で選んだ人の入力は、1人ずつ進みます**（生計維持者A → 生計維持者B → 詳しく計算する家族の順）。ページの見出しの下に「お父さん（生計維持者A）　1 / 3 人目」のように今の人が出て、［次へ：お母さん →］で次の人へ、最後の人のあとで次のページへ進みます。

| ページ | 内容 |
|---|---|
| 1 立場 | **どの立場で使うか**を選ぶ（学生本人／夫婦2人／ひとり）。選ぶと自動で次のページへ進みます。入力欄の呼び名が切り替わります |
| 2 お住まい | 都道府県・市区町村と対象の年分。**級地は市区町村を選ぶと自動判定** |
| 3 家族構成 | **同じ世帯にいる人を登録**。ここから扶養親族の人数・非課税限度額の判定人数・国保の被保険者数を**自動で数えます**。奨学金を調べるかどうかのチェックもここ |
| 4 所得 | 家族全員分（生計維持者A・B、詳しく計算する家族）の入力カードを縦に並べる。人ごとに「あてはまるものを選んでください」の2列のタイル（給与・年金・事業所得・不動産所得・副業などの雑所得・利子・配当・一時所得・車などの売却）で、**選んだ所得の欄だけ**を出します。最初は給与だけ選んであります |
| 5 所得控除 | 人ごとのチップ（社会保険料・iDeCo・医療費・生命保険料・地震保険料・ふるさと納税・雑損控除・その他）で**選んだ控除の欄だけ**を出します。最初は社会保険料だけ選んであります。本人の状況（③：勤労学生・ひとり親・寡婦・未成年・生活保護の生活扶助）も同じく「あてはまるものがあれば」選びます。最初は何も選んでおらず、その人に当てはまりようがない項目は出しません（お父さんの「寡婦」、18歳以上の「未成年」、夫婦〈生計維持者A・Bの両方がいる〉の「ひとり親」「寡婦」、「学生本人が使う」の親の「勤労学生」） |

| 7 繰越控除 | 「前の年から繰り越した損失がある人はいますか」に**ある／ない**。ある → 「誰ですか」→ 種類（株の譲渡損失／事業などの赤字（純損失）／災害・盗難の損失（雑損失）） |
| 8 税額控除 | 「住宅ローン控除などの税額控除を受ける人はいますか」に**ある／ない**。ある → 「誰ですか」→ その人の所得税・住民税の税額控除の欄 |

| 10 奨学金 | 「奨学金の条件を入力しますか」に**ある／ない**。ない → 大学・国公立・自宅から通学として判定。奨学金を調べないときはページごと飛ばします |
| 11 結果 | 判定結果。**［PDFで保存／印刷する］**→ 印刷ダイアログの「送信先／プリンター」で **「PDFに保存」** |

6〜8 で**「ない」を選ぶと、その欄に入れていた金額は0円に戻ります**（見えない所に数字が残って結果が変わらないようにするため）。
すでに金額が入っている欄のページを開くと、最初から「ある」が選ばれています。
チップを外したときも同じで、**外した項目に入っていた金額は0円に戻ります**。金額が入っている項目・人は、最初から選んだ状態で出ます。
「誰ですか」で、家族構成で「詳しく計算する」にしていない家族を選ぶと、その人を詳しく計算する人にして入力欄を作ります（株や退職金は扶養の判定にも効くため）。


1・2 ページの長い説明（「学生本人」と「夫婦」の違い、「年分」と「年度」のずれ）は畳んであります。制度の解説と出典は、結果のページの下に折りたたんで置いてあります。

結果のうち、要約・JASSO・国保の判定は最初から開いています。人ごとの明細（所得の計算・所得税・住民税）と出典は畳んであり、見出しか「＋」を押すと上から開きます。
入力して結果が計算し直されても、開いた明細は開いたままです。**PDF・印刷では畳んだ所もすべて開いて出ます。**

### スマートフォンで使うとき

**画面はスマホ基準です**（2026年11月から）。パソコンで開いても、スマホと同じ1列の幅（約600px）で真ん中に表示し、表も入力欄もスマホと同じ並べ方になります。印刷・PDF だけは紙の幅に合わせた広い並べ方です。

## 人数を自分で数えなくてよい仕組み（STEP 3）

世帯にいる人を「続柄・年齢・収入・同居・障害・だれの扶養に入れるか・国保加入」で1人ずつ登録すると、
その場で1人ずつ判定結果が表示されます。

```
19歳・給与収入0円      → 合計所得 0円 ≦ 58万円 → 特定扶養親族（19〜22歳）  控除 所得税63万／住民税45万
19歳・給与収入145万円  → 合計所得 80万円 が58万円超 → 扶養控除は不可だが 特定親族特別控除 の対象
                          （※非課税限度額の人数には含まれません）
19歳・給与収入250万円  → 合計所得 167万円 → 扶養に入れません
14歳・収入なし         → 16歳未満（年少扶養）。扶養控除はないが 非課税限度額の人数には含まれます
78歳・年金120万円・同居 → 合計所得 10万円 → 同居老親等  控除 所得税58万／住民税45万
```

生計維持者B（配偶者・お母さん）は **［削除］／［＋ 追加］** で出し入れします。
削除すると STEP 3 のB欄も STEP 5 の入力欄も消え、配偶者はいないものとして計算します（ひとり親の世帯はこの状態）。

生計維持者の続柄（お父さん／お母さん／その他）を変えると、
「だれの扶養に入れるか」の選択肢・見出し・追加ボタンの文言がすべて追従します。
父母が重複しないよう、片方を「お母さん」にすると、もう片方は自動で「お父さん」に入れ替わります。

## 家族1人ずつの詳しい計算（STEP 6）

各世帯員の行にある **「この人の税金も詳しく計算する」** にチェックを入れると、
その人にも A・B と同じ入力欄（分離課税・繰越控除・所得控除・本人の状況・税額控除）が STEP 6 に出ます。

- **学生本人が自分のアルバイト代・株の譲渡益・繰越控除・勤労学生控除を入力できます**（学生本人モードでは既定でON）
- その人自身の所得税・住民税も判定して結果に出します（自分の住民税が非課税かどうかも分かります）
- 入力した所得はそのまま**扶養に入れるかの判定**と**国保の軽減判定**に反映されます
- 控除のロックも同じように働きます（例：株の譲渡益30万円があると「勤労によらない所得が10万円超」で勤労学生控除がロック）

そのうえで、次の人数が自動で集計されます。

- 住民税の非課税限度額の**判定人数**（本人＋同一生計配偶者＋扶養親族。16歳未満を含む）
- A・Bそれぞれの**扶養親族の人数と内訳**（配偶者がいない場合はAの分だけ）
- 国保の**被保険者数**と**給与所得者等の数**、A・B以外の世帯員の所得合計

## 控除のロック（所得の条件を超えたら選べなくなる）

収入を入力した時点で条件を判定し、満たさない控除は自動的に無効化して理由を表示します。

| 控除 | ロックされる条件 |
|---|---|
| 勤労学生控除 | 合計所得金額が 85万円（令和8年分は89万円）を超えたとき／勤労によらない所得が10万円を超えたとき |
| ひとり親控除 | 合計所得金額が500万円を超えたとき／STEP 3 に「生計を一にする子」が登録されていないとき。母か父かは選択式（住民税の調整控除で人的控除の差が母5万円・父1万円と異なるため） |
| 寡婦控除 | 合計所得金額が500万円を超えたとき／ひとり親控除を選んでいるとき（併用不可） |

配偶者控除・配偶者特別控除（本人の合計所得1,000万円以下）や基礎控除（2,500万円超で0円）は、
STEP 4／5 の合計所得金額の欄に注意書きとして表示されます。

## 国民健康保険の軽減判定（令和8年度）

本サイトが出すのは**軽減割合（7割・5割・2割・なし）だけ**です。保険料率は市区町村ごとに違うため保険料額そのものは計算しません。

| 軽減割合 | 令和8年度の基準額（世帯の軽減判定所得がこれ以下なら該当） |
|---|---|
| 7割 | 43万円 ＋ 10万円 ×（給与所得者等の数 − 1） |
| 5割 | 43万円 ＋ **31万円** × 被保険者等の数 ＋ 10万円 ×（給与所得者等の数 − 1） |
| 2割 | 43万円 ＋ **57万円** × 被保険者等の数 ＋ 10万円 ×（給与所得者等の数 − 1） |

賦課限度額：医療分 67万円（＋1万円）＋支援金分 26万円＋介護分 17万円＋**子ども・子育て支援納付金分 3万円（令和8年度新設）＝ 113万円**。

### だれが「被保険者」か

国保は世帯単位ですが、**同じ世帯の全員が被保険者とは限りません**。判断の基準は世帯分離の有無ではなく、**加入している健康保険の種類**です。

- 会社の健康保険（協会けんぽ・組合健保・共済）に入っている人と、その**被扶養者は国保ではない** → チェックを外す
- 世帯全体が国保（自営業など）なら、**子どもも一人ひとりが被保険者** → チェックを入れる（0歳でも均等割がかかります）
- **擬制世帯主**：世帯主が会社の健康保険でも、世帯内に国保加入者がいれば**世帯主の所得は軽減判定に含める**（均等割の人数には入らない）
- **特定同一世帯所属者**：後期高齢者医療制度へ移行後も同じ世帯にいる方。軽減判定では被保険者と同様に数える

被保険者数を1人少なく数えると5割・2割の基準額が31万円／57万円ずつ下がるため、判定が変わることがあります。

**特定同一世帯所属者の数だけは STEP 3 から判別できない**ため、STEP 7 で直接入力します（いなければ0のまま）。

### 人数の入力口は2つあり、片方を選ぶともう片方はロックされます

国保の人数・所得を決める入口は2つあり、**実際に使われるのは一方だけ**です。
どちらが効いているのかが分かるよう、使われないほうは操作できないようにして理由を表示します。

| 状態 | 効いているもの | ロックされるもの |
|---|---|---|
| 既定（自動計算） | STEP 3 の「この人が国民健康保険の被保険者」チェック | STEP 7 の被保険者数・給与所得者等の数・そのほかの世帯員の所得 |
| 「上の3つを手入力した値で計算する」にチェック | STEP 7 に入力した数値 | STEP 3 の加入チェック |

ロック中も値は保持されるので、チェックを外せば元の状態に戻ります。

### 軽減判定所得は住民税の所得と少し違う

| 項目 | 軽減判定所得での扱い |
|---|---|
| 所得控除（基礎控除・社会保険料控除など） | **差し引かない** |
| 退職所得（一時金） | **含めない** |
| 純損失・雑損失の繰越控除 | **適用した後**の額 |
| 65歳以上の公的年金等に係る所得 | さらに **15万円**を控除 |
| 土地建物等の分離譲渡所得 | **特別控除前**の額（住民税の所得割は特別控除後なので逆） |
| 事業専従者控除・青色事業専従者給与 | **事業主の所得に戻す**（専従者側の所得は0とみなす） |

分離譲渡の特別控除額と専従者の額は STEP 7 で足し戻せます。

## 「合計所得金額」と「総所得金額等」の違い（繰越控除がある場合の要点）

| | 合計所得金額 | 総所得金額等 |
|---|---|---|
| 繰越控除 | **適用する前**の金額 | **適用した後**の金額 |
| 使われる場面 | 住民税**均等割**の非課税判定／扶養・配偶者控除の判定／基礎控除・勤労学生控除の所得要件 | 住民税**所得割**の非課税判定／所得割の課税標準額／医療費控除の足切り／国保の軽減判定 |

株式の譲渡損失などを繰越控除していると、**「所得割は非課税なのに均等割は課税される」「扶養から外れる」**ということが起こります。
本サイトは両方を分けて計算し、結果画面で明示します。

## 均等割と所得割の違い（本サイトの中心テーマ）

| | 均等割 | 所得割 |
|---|---|---|
| 課税の考え方 | 定額（会費的） | 所得の大きさに応じる |
| 税額 | 市町村3,000円＋道府県1,000円＋超過課税＋森林環境税1,000円 | 課税標準額 × 10％ − 調整控除 − 税額控除 |
| 所得控除の影響 | **受けない** | **受ける** |
| 非課税限度額（単身） | 合計所得金額 ≦ 45万円（1級地）／41.5万円（2級地）／38万円（3級地） | 総所得金額等 ≦ 45万円（全国共通） |
| 扶養がいる場合の加算 | ＋21万円（1級地） | **＋32万円** |
| 奨学金との関係 | — | **所得割が非課税なら必ず第Ⅰ区分（満額）** |

扶養親族がいる世帯では加算額が異なるため、**「均等割は課税・所得割は非課税」**という状態が生まれます。
この場合でも JASSO の支援区分は**第Ⅰ区分**です。

## 注意事項

- 本サイトは公表資料に基づく**概算・目安**です。実際の税額・保険料・奨学金の採否を保証するものではありません。
- **都道府県・市町村の超過課税には課税期間があり、延長・廃止されることがあります。** 均等割額・税率は画面上で手動修正できるようにしてあります。
- **級地区分**は生活保護法の級地（厚生労働省告示第158号）を収録し、毎月の確認で現行の別表第9と全件照合しています。合併・指定替えで変わることがあるため、画面上で手動変更もできます。結果画面には3級地すべての限度額を併記しています。
- 国民健康保険の**保険料率は市区町村ごとに異なる**ため、軽減判定のみを行い保険料額そのものは算出しません。
- 分離課税分の住民税は**標準税率**（合計5％、短期譲渡は9％）で計算しています。市町村民税と道府県民税の内訳は政令指定都市 4：1、それ以外 3：2 で按分し、自治体独自の超過課税・減税は総合課税分にのみ反映しています。
- 住宅ローン控除の限度額計算、居住用財産の3,000万円特別控除などの各種特例には対応していません（控除額・特別控除後の金額を入力してください）。寄附金控除はふるさと納税を含めて計算しますが、条例で指定された寄附金の自治体ごとの扱いには対応していません（基本控除だけ計算します）。
- 令和8年分の所得税・令和9年度の住民税は公表資料で確認済みですが、**令和9年度の国民健康保険は令和8年度の基準で判定**しています（基準額は例年3月末公表）。
- JASSO の判定では、**収入基準以外の要件（学力・在学・国籍／在留資格・資産基準）はすべて満たしている前提**としています。

情報の時点は、画面のヘッダーに出る「税制データの最終確認」の日付です。
